# Contributing

Hardware Atlas grows through small, tested project guides.

## Add a project

A project should state:

- what is being built;
- what will be learned;
- prerequisites and difficulty;
- components, tools, and software;
- what to measure or test;
- reliable resources;
- what to build next.

Prefer a modest project with a clear measurement over a large project that hides the learning. Include a schematic or wiring description, expected observations, common mistakes, and relevant safety notes.

## Add a resource

Use official manufacturer documentation, datasheets, actual community pages, or a source you have checked recently. Never invent a URL. Say what a resource is useful for instead of dropping a bare link. Avoid unsupported claims about sellers, markets, or authenticity.

## Metadata

Markdown is the primary interface. YAML is only for lightweight project and resource metadata that helps contributors maintain the repository. Keep it readable and do not turn the project into a database.

Before opening a pull request, check local Markdown links, parse changed YAML, and read the page as a beginner would. Prices, stock, addresses, opening hours, and links can change, so date or qualify time-sensitive information.
